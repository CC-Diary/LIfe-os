# 档案格式

数据根目录：
- config.json：路径、访谈偏好、隐私约定。
- state.json：进度、最后更新、待确认事项；仅作索引，不重复敏感内容。
- profile.md：当前画像，按领域保留少量相关事实及来源。
- hypotheses.md：推测、依据、反证条件、状态。
- evidence.md：重要判断对应的证据条目、来源等级和状态；不重复保存敏感原文。
- life-model.json：机器可读索引，连接 events、values、patterns、decisions、outcomes 和 belief_changes；具体字段以 本 Skill 的 schemas/ 为准。
- life-model.md：跨 Agent 的人类可读入口；不同 Agent 先读它，再按需读取详细文件。它不是完整档案，不为空不代表用户没有相关经历。
- plans：计划对象单独记录意图、时间窗口、约束、调整规则和执行状态；健康计划可标记为 `local_only`，不自动进入长期人格档案。
- events/*.md：有日期与来源的经历记录。
- decisions/*.md：决策依据、选择与后续结果。
- private/：用户自己维护的禁止主动读取区域。

记录字段：ID、记录日期、事件发生时间（可为未知或大约）、内容、来源、状态（用户陈述/用户确认/AI推测）、敏感级别（普通/敏感/local_only）。
来源用“当前对话，用户于 YYYY-MM-DD 的自述”或具体事件文件 ID。不要编造聊天消息 ID。
用户陈述表示原意被保存，不表示经过外部核实。本人姓名、年龄和职业未知时留空，不从目录名推断。人格标签必须能回指具体事件；AI 生成或未确认内容不得直接写入长期事实。

事实更新：先读原文件，只修改相关条目，避免覆盖其他会话的最新记录；写入后回读。不同说法保留情境与时间，当前摘要以更新后的情况为准。
事件 ID 使用日期加短标识，冲突时追加序号。不把未知发生日期替换为记录日期。
决策记录至少含选项、关键约束、事实引用、假设、用户最终选择（未知时留空）、复盘指标。

删除：在画像、推测、事件、决策及状态索引搜索关联内容，删除或脱敏派生信息。不要为了“审计”重新保存已删除原文。
迁移：先检查 schema_version，不理解的版本不要重置。搬家时复制整个数据目录并验证文件，再更新配置；未经授权不要删除旧目录。

此版本无数据库、无向量索引、无自动后台同步。通过文件检索获得记忆，依赖后续代理重新读取文件。
